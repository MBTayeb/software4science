The toolbox philosophy

While you can use unix-like systems like Windows via graphical user interfaces (GUIs), their real strength is their CLI. (Read more on CLIs on a previous unit.) Why would you want to do that? First, you can avoid GUIs, which saves resources and is possible also on (even remote) computers where no graphical output is available. But it is even more important that, you can put your commands into scripts (small programs), to automate the work you are doing. As the time goes, you build up a toolbox of scripts using simpler scripts, and so an, based on the basic commands.

This philosophy of having small programs for specific tasks and solving more complex problems by 'piping' (handing over) data from one to the other is the core of shell scripting. You should always strive to write scripts instead of doing things by hand, to increase the reproducibility of your work. In fact, if you make errors by hand, they are often basically impossible to find, but if your script contains an error, the problem is much easier to spot, as it occurs in a regular fashion. Also, if things go wrong, with a script you can simply delete the whole lot and easily set up directories, files etc. again (and again, ...). 

By the way, Windows offers PowerShell for the same purpose, but it's different that Linux shells which are simple at the bottom and would turn to a proper scripting language like Python for more complex tasks. (This is the tool box philosophy.) PowerShell is a somewhat unfortunate mix-up of a basic shell and a more powerful scripting language. (Feel free to disagree, of course!) Important commands/tools

To feel at home on a Unix-like system, it helps to know common command-line tools for navigating directories and managing files. Bash (Bourne Again Shell) and Zsh (Z shell) are among the most widely used Unix-like shells. Bash is common on Linux systems, while Zsh is the default shell on modern macOS.

Bash and Zsh have some differences in syntax and behavior, but for basic command-line tasks, those differences usually matter little. Many commonly used tools, such as cat, grep, and find, are separate programs, not commands specific to either shell. You can use them from Bash, Zsh, and many other shells, so learning them transfers well. This reflects the Unix philosophy of combining small tools.

One caveat: command-line tools can differ between operating systems. macOS includes many BSD-derived tools, while Linux distributions commonly provide GNU versions. Most everyday usage is similar, but some options behave differently. For example, sed -i takes different forms on macOS and GNU systems.

Vi

Another central tool is the editor Vi, because work in a shell usually means the editing of files and Vi is the editor you will find on literally every machine. Vi has a marvelous list of functions, but if you don't like Vi, I would still recommend learning how to use it to just edit files (which is easy, so don't worry). Find more on this in a following chapter.

SSH

A very useful tool is SSH ('secure shell') which allows you to access remote computers from your shell via a cryptographic network protocol. It works as easy as 'ssh user@remotecomputer' and afterwards whatever you type will be executed on the distant machine. NWZ computers usually do not allow direct SSH access from outside the university network. To get around this, first hop to the CIT ssh and then make another hop to the machine you want to access (it still has to allow for SSH access). Read more in https://www.uni-muenster.de/IT/en/services/arbeitsplatz/jumphost/index.html .

Where To Find Help

To learn more about specific commands you can either:

  • call the command with the -h or --help option (good to look up certain options you always forget again)
  • type info command or man command (good to get a basic idea of the usage)
  • Directly google whatever you are interested in, e.g. "bash echo". You will often find a forum post explaining it on StackExchange or similar.
  • Install tldr: "collaboratively made simple cheatsheets for console commands" tldr stands for "Too Long; Didn't Read" xD https://tldr.sh/#installation or browse it on https://tldr.inbrowser.app/ Note, once you open this website online, its content will be saved in the cache of your browser, so that you can reach it even without internet access.
