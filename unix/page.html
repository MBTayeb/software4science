What is Linux?

Linux is an open-source kernel. The kernel is the core of an operating system (OS): the part that manages the hardware and lets programs run. Operating systems built on Linux offer an alternative to Windows and macOS. However, unlike those, there isn't a single Linux OS, but a whole range of distributions (or just distros). This variety has its own advantages and disadvantages. In addition, there are many special-purpose OSs like Android, which are based on Linux.

What is Unix?

In fact, Linux exists only because of decades of earlier work on operating systems (OSs) in the second half of the 20th century, far more than we can cover here. One of the most influential ones was Unix, which Ken Thompson, Dennis Ritchie, and others began developing at Bell Labs in 1969. Unix has since received many updates and forks. A notable one is BSD (short for Berkeley Software Distribution), developed at UC Berkeley. Today, macOS is built on a foundation that includes a large amount of BSD code.

In 1991, Linus Torvalds released the Linux kernel. Linux was not built from Unix code. Instead, it was written from scratch to work like Unix, which is why it is called "Unix-like." Because of this history, most major operating systems today, including Linux, macOS, Android, and iOS, are Unix or Unix-like. Windows is the main exception. (Interestingly, before releasing Windows, Microsoft sold its own version of Unix called Xenix.)

Why should you care about "Unix-like" sytems?

While the desktop consumer market is clearly dominated by Windows, a lot of 'serious' (and loads of not-so-serious) IT-stuff beyond this is usually done under Unix-like systems. These shine especially in the area of embedded and/or scientific computing and high-performance computing (HPC). A core reason for this is that the open source approach is self-enhancing: evermore useful tools are developed on the basis of easily accessible existing tools.

Unix-like systems differ in many details, but they share a common way of working. In other words, what you learn on one Unix-like system largely carries over to all the others. A script written on your laptop will usually run on a university compute cluster with little or no change, and most scientific software, tutorials, and documentation assume this kind of environment.

Choosing a Linux distribution

Nowadays, there are a lot of Linux distributions. They can have the same look-and-feel as Windows or macOS, if you like. They also offer pretty much all the functionality of Windows, plus access to the world of Linux via package management systems that allow you to install new software tools with one line in your terminal. Some distributions are community-driven but commercially backed, i.e. supported by IT companies. Let's name some examples (the name of the company is put in parenthesis): Fedora (Red Hat), openSUSE (SUSE), Ubuntu (Canonical Ltd.). Some distributions are entirely community-driven, like Debian or Arch Linux, and they oftentimes offer just a basic system and a package management system.

I would still recommend to choose one of the more commonly used distributions like openSuse, Ubuntu, and Mint.

How to Run Linux?

There are many ways how to run Linux and keep your current OS: The most obvious one is to get a second machine. The probably less obvious one is that you can install more than one operating system on a machine, e.g. as dual boot for Linux and your currend OS. But as nowadays virtualization technology has become quite good, it is usually easier to run the second OS in a virtual machine. (Most OSs allow hosting a virtual machine.)

Another convenient option is to run linux on a distant server. The easiest way is with the JupyterHub service provided by the university. After logging in, you can keep the default settings and press start at the bottom of the page. Then, scroll down on the launcher tab and select terminal. Congratulations! You are running a linux terminal from your personal virtual machine on the cloud. Other similar services might be offered by the CIT or IVV NWZ or your group...
