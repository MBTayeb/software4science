Keeping all that in mind I would like to recommend the following strategy here:

  1. Start with learning Bash, so that you feel comfortable operating a Linux system especially when writing scripts to automate your work.
  2. Then visit Fortran; it's still very much at the center of scientific computing and the basics are not hard to get; it is very straightforward mathematical programming.
  3. For doing your actual research move on to Python: it is much less demanding than C++ and usually everything you could only wish for not to write yourself will be available.
  4. Once your project turns quasi-professional or if you anyhow have the intention to make it that way, C++ will offer everything you need. (But be prepared to spend most of the time planning to write code, instead of actually writing it).
  5. Finally, if a project requires it, learn R, Matlab, SQL etc. This should be relatively easy, since learning a second programming language mainly involves re‑learning the same concepts with a different syntax.

In this course, we will follow the strategy outlined above and focus on Bash, Fortran, and especially Python. This strategy may not suit every scientific discipline, particularly those that belong to bio‑ or geo‑informatics, fields that developed long after the heyday of Fortran. In such cases, it is often better to start with Bash and then move on to R, MATLAB, or whatever language is the community’s accepted standard. If you have worked through this unit, you have learned some 'universal' features of programming languages already:

First, variables need to be assigned (and sometimes declared, i.e. they need to be given a type).

Second, the flow of programs requires control structures like loops, conditions etc.

And third, sub-units (functions, subroutines, modules, etc.) are needed to structure code.

Apart from this, there is some general stuff to remember for each language. For example, what line defines the start of a program or how to do in- and output etc. When learning a new programming language, you are often times fine with remembering just the basics. If you then look for the correct 'syntax' of an element, it's usually best practice to google it ("fortran loop"), once you have understood what you are looking for.

Online resources for learning Fortran:

Fortran’s compiled nature means you must learn both the language and its compiler, including library management. As codebases expand, manual compilation becomes tedious, so learning a build system such as make is recommended.

One of the reasons why Fortran provides such excellence performance is the existence of very high-quality compilers (the Intel Fortran compiler is a legend), which manage to produce extremely fast code. But unlike in the past, C++ compilers (including the GCC one) don't seem to be utterly behind anymore.

The use of software libraries is essential for good programming! Libraries provide code written by someone else (usually more clever than you or me) that can be reused for your purposes. You still need a good understanding of the third-party code to provide it with the correct inputs and know what results to expect.. If you learn how to use libraries you can save a lot of time by not re-rewriting existing code, which in addition is usually much more error-proof than the ugly hack you just made up.

The use of a build system like make is also considered good programming, as it allows not only you, but also other people to compile your code conveniently (or: at all).

You will learn more about compilers, software libraries in another subchapter and build systems in the next work unit.
