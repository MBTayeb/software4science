Doing RSE work usually means to write (source) code in a programming language. The proper choice of the languages is not obvious or unambiguous, so it is worth the time to spend some thoughts on this issue.

There is a very large number of programming languages available and although for most of them there are good reasons why they are used for their specific applications, some languages a certainly better suited for scientific work. A core difference between languages is whether they must be compiled (turned into machine-readable binaries via a compiler before execution) or whether they are interpreted, i.e. written as scripts which are read and executed by a separate program. Fortran would be an example for the former, Python for the latter.

Compiled languages usually have static typing (variables must be defined as being of a certain type, e.g. a real number, or a string of characters), but compilation can be optimized in several ways and is hardware-specific, so that compiled languages are considered to deliver high performance. Accordingly, most high performance computing (HPC) applications are based on compiled languages like Fortran or C/C++. Interpreted languages usually have dynamic typing (the type of variables is determined upon execution, depending on what values are given) and are considered to be better suited for the quick and easy development of software solutions, also since there is no time-consuming compilation step involved. Some new languages like Julia promise to provide both high performance and easy development with just-in-time compilation. (Although for now I don't think Julia can be recommended as a first programming language, you will probably hear a lot of praise for Julia from experienced HPC people, which is why there is a separate work unit below on Julia.) Apart from performance, the existing software ecosystem of a language is very important for the proper choice of a programming language. Fortran, "the mother tongue of scientific computing" (C.E. Leith), is still at the center of HPC, first of all because there is a huge ecosystem of existing code, libraries, tools, etc. available, that makes it easy to develop scientific applications in fortran, especially concerning so-called number-crunching tasks (the computation of huge numbers of mathematical operations). C/C++ is arguably the most widely used language for high-level commercial work, so that a large pool of professional software tools is available for C/C++, which has made C/C++ very attractive for larger scientific software projects in recent years. Considering interpreted or scripting languages, Python is well established in many fields in- and outside of science, so that with this programming language easy access to new technologies is available (cloud computing, machine learning etc.).

Once you have mastered one or two programming languages, you will see that the core elements of programming languages are rather universal and that learning new languages is often not more complicated than memorizing a new syntax and probably keeping a few odd features in mind. (The concepts of object oriented programming (OOP) or functional programming are an exception: they are the basis for other languages like Python as an OOP language and Haskell as a FP one. We will therefore have to learn about these in a unit devoted to them called programming paradigms.) This means that when choosing your programming languages you don't have to worry too much about ending up in a dead end. Considering performance and environment, the choice of programming languages for scientific applications is practically often less confusing than it initially seems, as it often simply makes sense to stick to popular solutions, for which a large pool of clever people constantly work on both performance and new tools.

You will find that while Java, C/C++ and Python are most popular for professional software development, the most popular languages in science are Python, C/C++, Fortran (for HPC), and less general languages like R, Matlab, etc. These lists often do not include scripting languages like Bash, which underlie the functionality of command-line interfaces themselves (CLIs, which basically means the terminals you're typing into), which is why in addition everyone should have at least a basic understanding of their CLI language.

Keeping all that in mind I would like to recommend the following strategy here:

  1. Start with learning Bash, so that you feel comfortable operating a Linux system especially when writing scripts to automate your work.
  2. Then visit Fortran; it's still very much at the center of scientific computing and the basics are not hard to get; it is very straightforward mathematical programming.
  3. For doing your actual research move on to Python: it is much less demanding than C++ and usually everything you could only wish for not to write yourself will be available.
  4. Once your project turns quasi-professional or if you anyhow have the intention to make it that way, C++ will offer everything you need. (But be prepared to spend most of the time planning to write code, instead of actually writing it).
  5. Finally, if a project requires it, learn R, Matlab, SQL etc. This should be relatively easy, since learning a second programming language mainly involves re‑learning the same concepts with a different syntax.

In this course, we will follow the strategy outlined above and focus on Bash, Fortran, and especially Python. This strategy may not suit every scientific discipline, particularly those that belong to bio‑ or geo‑informatics, fields that developed long after the heyday of Fortran. In such cases, it is often better to start with Bash and then move on to R, MATLAB, or whatever language is the community’s accepted standard. Bash can be learned in a previous unit. If you have worked through it, you would have learned some universal features of programming languages already:

First, variables need to be assigned (and sometimes declared, i.e. they need to be given a type).

Second, the flow of programs requires control structures like loops, conditions etc.

And third, sub-units (functions, subroutines, modules, etc.) are needed to structure code.

Apart from this, there is some general stuff to remember for each language. For example, what line defines the start of a program or how to do in- and output etc. When learning a new programming language, you are often times fine with remembering just the basics. If you then look for the correct syntax of an element, it's usually best practice to look it up online ("fortran loop"), once you have understood what you are looking for.
