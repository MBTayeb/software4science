Terminals

Most OSs/distros provide a terminal emulator by default, but they might not be the best option. Just search for terminal or console to find them. This unit is optional, but a good terminal helps you feel at home in the command line and can take your CLI experience to another level.

We focus here on terminals that are cross-platform. The term can mean different things, but we mean here that it is available in Windows, macOS, and Linux. Still, we will mention some that run on only one or two of these but shine there.

Terminals differ in how you configure them, which matters for reproducibility. A text-based configuration file can be used to recreate the same setup in a new machine. We use three terms to describe configuration styles:

  • GUI-configured: settings are changed only through graphical menus. They are stored internally and are not meant to be edited by hand.
  • File-configured: settings live in a plain-text file (for example, TOML, YAML, JSON, or Lua) that you edit directly. There is no graphical settings menu.
  • Hybrid configuration: settings can be changed either through a graphical menu or by editing text files. Both stay in sync, so a change in the menu is written to the file, and vice versa.

Terminal multiplexers

Terminal multiplexers let you run several shell sessions inside a single terminal window, arranged as tabs or split panes. This has two main advantages. First, they add tabs and pane splitting to any terminal, even a simple one that lacks these features. Second, the sessions run independently of the terminal window. If the terminal closes or crashes, or your SSH connection drops, the sessions keep running, and you can reattach to them later. Popular examples include tmux, and Zellij.
